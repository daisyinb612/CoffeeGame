# 任务
同时理解输入视频的画面和原声，输出可供剪辑核对的中文动作时间线。动作只写画面确实可见的事实；原声可帮助理解操作顺序与意图，但不能代替画面证明动作已经发生。不要按常识或预设流程补动作。示例仅说明输出格式，绝不是输入视频的内容。

# 分段规则
1. 一个 segment 对应一个明确的操作目标或交互过程。目标、交互物品或物品状态发生变化时，另起一段。不要把取物、清洗、使用、归位等不同操作合成一句话。持续等待或持续搅拌这类单一过程可以是一段。
2. 按画面发生顺序覆盖所有可见的重要动作。只移动镜头或走到另一处时，如无物品操作，可单独记录为移动过程；不得借此推断下一个操作已经发生。
3. 时间从输入视频的 00:00 开始，使用 MM:SS；必要时可使用 MM:SS.s。起止时间尽量贴近动作，不得超过视频长度。相邻段可紧接，不必制造停顿。

# 每段字段，字段名不得更改
- start_time / end_time：本段动作起止时间。
- scene：画面实际显示的区域、视角，以及与本段动作有关的物品位置。写当前画面，不写操作意图。
- action：谁对什么做了什么；写出可见的先后顺序和动作结束时可见的结果。不要使用“进行准备”“处理物品”这类空泛说法。
- objects：只列出本段被触碰、手持、移动或使用的物品；每项包含 name、description（可见外观或位置）、interaction（可见交互方式）。仅在背景出现的物品不列入。没有交互物品时写 []。
- evidence：支持 action 的直接画面线索，例如手的位置、物品移动、液体流动；不能只重复 action 的结论。
- audio_context：这一段确实听到的相关讲解或声音线索，用简短中文概括；可写说话者解释的目的、数值或下一步，但不要在这里逐句转写。没有相关原声时填 null。原声与画面不一致时明确写出，不要替画面补动作。
- uncertain：动作或关键物品的识别有疑问时写 true，并在文字中说清看不清之处。不要为了显得确定而填 false。
- transition_to_next：本段结束后如何进入**紧接着的下一段**。description 应连接本段结束状态与下一段开始状态，可描述手持物品的去向、人物或镜头移动、画面剪切；若原声明确说明下一步，也可注明“原声提示下一步……”。原声说到的下一步尚未出现在画面时，不得当成已经发生。没拍到过渡时写“画面未显示过渡过程”，uncertain 写 true。最后一段必须是 null。

# 停顿候选
transition_windows 只列确实可见的、两个操作之间没有继续动作且没有走动或移动镜头的停顿。普通转身、走路、镜头摇转和物品移动不属于停顿。没有明确停顿就写 []。

# 真实性检查
没有看到物料进入容器，就不要写容器里多出了物料；没有看到按键或设备工作，就不要写启动设备；读不清数字就不要编造数值。可以写“手持透明容器靠近设备”，不要把尚未发生的使用动作写进去。每个 objects.interaction 和 transition_to_next.description 也必须有画面依据。若过程被遮挡或跳过，明确写不确定。

# 输出要求
只返回一个有效 JSON 对象，不要 Markdown、解释或英文描述。顶层只有 segments 和 transition_windows。输出前检查：字段齐全、时间有序且在片长内、动作有画面依据、原声线索写在 audio_context、每个非末段都有到下一段的过渡、末段过渡为 null。逐句转写由独立音频步骤完成，这里不要求列出所有语句。
